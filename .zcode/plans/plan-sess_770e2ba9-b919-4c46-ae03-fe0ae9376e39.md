# Hardening `clikader setup`: real SSH port/auth changes, ufw → nftables, verifiable fail2ban

## Root causes found (why the script "says everything is good")

1. **SSH port not actually changed** — three separate mechanisms, all silent:
   - Debian 11+ has `Include /etc/ssh/sshd_config.d/*.conf` at the **top** of `sshd_config`. sshd is first-value-wins, so a provider drop-in (e.g. `50-cloud-init.conf`) overrides what we append at the bottom; `Port` is even worse — multiple `Port` lines mean sshd listens on **all** of them.
   - **Debian 12/13 socket activation**: when `ssh.socket` is active (default on bookworm/trixie images), systemd listens on `ListenStream=22` and `Port` in `sshd_config` is completely ignored. Restarting sshd "succeeds" while the listener never moves.
   - The script only runs `sshd -t` (syntax check) and never verifies the **effective** config or the **actual listener**.
2. **Auth directives** — same drop-in precedence problem for `PasswordAuthentication` (cloud-init drop-ins commonly set `yes`) and `PubkeyAuthentication` (some providers set `no`). Combined with our `PermitRootLogin prohibit-password`, that means either password auth silently stays on, or total root lockout. Also, `authorized_keys` is installed *after* sshd restart — wrong order for lockout safety.
3. **fail2ban** — current config is close (backend=systemd is already pinned per-jail, which is the known Debian fix), but `banaction` is not pinned (distro default may be iptables-*), `journalmatch` is not pinned (unit-name mismatch `sshd.service` vs `ssh.service` is the classic silent no-match failure), and there is **no end-to-end verification** that a ban actually lands in the firewall.

## Changes — all in `components/setup_vps.sh` unless noted

### Step 5 rewrite: `step_ssh_hardening`
- **Recon first**: report the effective port(s) (`sshd -T`), whether `ssh.socket` is active, and any drop-ins present in `/etc/ssh/sshd_config.d/`.
- **Scrub drop-ins**: comment out `Port`, `PermitRootLogin`, `PasswordAuthentication`, `PubkeyAuthentication`, `KbdInteractiveAuthentication` in `/etc/ssh/sshd_config.d/*.conf` (each modified file backed up with `.backup_<ts>`).
- **Managed block at top of main config** (replaces delete-and-append-at-bottom; idempotent — old `# BEGIN/END clikader` block removed first):
  ```
  Port <ssh_port>
  PermitRootLogin prohibit-password
  PasswordAuthentication no
  PubkeyAuthentication yes
  KbdInteractiveAuthentication no
  ```
  Placed at line 1 so it wins over everything below (and over any future provider drop-ins, since the `Include` line sits below it).
- **authorized_keys installed BEFORE any sshd restart** (lockout safety).
- **Socket activation**: if `ssh.socket` is active/enabled → `systemctl disable --now ssh.socket` + `systemctl enable --now ssh.service` (Debian-sanctioned way to make `Port` effective again), with a log line explaining why.
- **Post-restart verification** (the actual fix for "says everything is good"): `sshd -T` must show `port <ssh_port>`, `passwordauthentication no`, `pubkeyauthentication yes`; `ss -tln` must show a listener on `<ssh_port>` and warn about any sshd listener left on another port. Loud error + non-zero exit on mismatch.

### Step 6 rewrite: `step_configure_ufw` → `step_configure_nftables`
- Package list: drop `ufw`, add `nftables`.
- Generate `/etc/nftables.conf` (original backed up) with **clikader-owned tables only** — never `flush ruleset`, so a reload doesn't wipe fail2ban's table mid-run. Idempotent via `add table X` + `delete table X` before the full declaration (works on older nft too, no `destroy` needed):
  - `table inet clikader_filter`: input policy drop (lo, ct established/related, ct invalid drop, icmp + icmpv6 allowed, DHCP client replies `udp sport bootps dport bootpc` allowed — ufw allowed this implicitly via before.rules), SSH port tcp, extra ports tcp+udp (parity with `ufw allow <port>`), counter drop; forward chain (policy drop, established/related accept) reserved for future port forwarding; output accept.
  - `table inet clikader_nat`: empty `prerouting`/`postrouting` chains with commented DNAT + masquerade examples, so adding a future forward-to-another-machine rule is a one-liner.
- Validate with `nft -c -f` **before** applying; then `systemctl enable --now nftables` (restart if running); show the loaded table.
- **Migration**: if ufw is active → `ufw --force disable`; if installed → purge it. (Fresh installs never get ufw; existing servers migrate when re-run with `--force`.)

### Step 7: fail2ban config + functional self-test
- `jail.local` gains: `banaction = nftables-multiport`, `banaction_allports = nftables-allports` (explicit, independent of distro defaults), and `journalmatch = _SYSTEMD_UNIT=sshd.service + _SYSTEMD_UNIT=ssh.service` (covers Debian's unit name).
- After `fail2ban-client -t` + enable/reload: show `fail2ban-client status sshd`, then run an **end-to-end ban self-test**: `fail2ban-client set sshd banip 192.0.2.1` (TEST-NET doc IP) → verify it appears in `nft list ruleset` → `unbanip`. If the ban doesn't land in nftables, print a loud warning that banning is broken. Also point the user at `/var/log/fail2ban.log` for future ban logs.
